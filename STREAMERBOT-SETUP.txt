STEP 1 — ENABLE THE WEBSOCKET SERVER
--------------------------------------
1. Open Streamer.bot
2. Go to:  Servers/Clients → WebSocket Server
3. Check "Auto Start" and click "Start Server"
4. Default port: 8080
   NOTE: If you change the port, update it in assets/config.js:
         port: 8080   ← change this to match

STEP 2 — CONNECT YOUR PLATFORMS
---------------------------------
Twitch:
  1. Go to: Platforms → Twitch → Accounts
  2. Click "Add Account" and log in with your Twitch account
  TODO: Your Twitch channel name = FlammableBump (update in assets/config.js if different)

Kick:
  1. Go to: Platforms → Kick → Accounts
  2. Click "Add Account" and log in with your Kick account
  TODO: Your Kick channel name = FlammableBump (update in assets/config.js if different)

YouTube:
  1. Go to: Platforms → YouTube → Accounts
  2. Click "Add Account" — this opens a Google OAuth login in your browser
  3. Log in with your Google account that owns the YouTube channel
     IMPORTANT: If your channel is a Brand Account (not a personal channel),
     you must log in with the primary Google account that manages it.
     YouTube does not allow Brand Account direct OAuth — you authenticate
     with the owner account and Streamer.bot then accesses the brand channel.
  4. After logging in you'll see "Broadcaster" and optionally "Bot" account slots.
     For most setups, Broadcaster is all you need.
  5. Enable "Auto Connect" so Streamer.bot reconnects on startup.
  6. Under Platforms → YouTube → Settings, enable:
       - Track Live Chat
       - Track Viewer Count (StatisticsUpdate events)
  7. Streamer.bot streams YouTube via the YouTube Data API v3 —
     viewer count updates may be delayed 60–90 seconds vs real-time Twitch.
  NOTE: YouTube requires an active broadcast (live stream) to receive events.
        Events won't fire during test/offline mode the way Twitch does.

STEP 3 — CREATE YOUR ACTIONS
------------------------------
You need two actions in Streamer.bot for the control panel to work:

ACTION 1 — "Game Switch" (sends game/title to overlay)
  - In the Actions tab, click the + button to create a new action
  - Name it: "FB Game Switch" (or whatever you like)
  - Add a sub-action: Core → WebSocket → Broadcast (or use Execute C# Code)
  - This action receives { game, title } from the control panel
  - After creating it, right-click the action → Copy ID
  TODO: Paste that ID into widgets/control-panel.html:
        const SB_GAME_ID = "PLACEHOLDER-GAME-ACTION-ID";
        Replace PLACEHOLDER-GAME-ACTION-ID with your actual UUID

ACTION 2 — "Fire Alert" (broadcasts alert to OBS browser sources)
  - Create another action: "FB Fire Alert"
  - Add a sub-action: WebSocket → Broadcast
    - Channel: flammablebump:alert  (or use a Custom Event broadcast)
  - After creating it, right-click the action → Copy ID
  TODO: Paste that ID into widgets/control-panel.html:
        const SB_ALERT_ID = "PLACEHOLDER-ALERT-ACTION-ID";
        Replace PLACEHOLDER-ALERT-ACTION-ID with your actual UUID


STEP 4 — OBS SETUP
--------------------
Make sure the overlay server is running first:
  Double-click start-overlay.bat
  Then go to http://localhost:3001 in your browser to see all URLs

In OBS:
  1. Add a Browser Source for each scene/widget
  2. Check "Local file" OFF — use the http://localhost:3001/... URLs
  3. Check "Shutdown source when not visible" ON for scenes
  4. Check "Refresh browser when scene becomes active" ON for scenes
  TODO: Your OBS port for Browser Source interactions, if using OBS WebSocket:
